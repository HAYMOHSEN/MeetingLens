What was fixed

All items below refer to the corrected candidate. High severity means a broken deliverable, missed shared edits or a risk to saved work.

PriorityObserved problemCorrection and evidence
HighPDF-01PDF downloads could not be opened

The PDF writer emitted literal backslash-n characters instead of PDF line breaks.

Fixed PDF syntax and cross-reference offsets. Strict parsing and independent rendering pass.

Automated regression; real browser download; pypdf and MuPDF.
HighSYNC-01Edits made during Team publishing could be missed

The client marked the current state as saved after an older snapshot finished uploading; title-only edits were not tracked.

Track the submitted revision separately, keep later edits pending, include title changes, and pin/abort connections when disconnecting.

Two browser clients; delayed upload; automatic next revision; title-only receiving; feedback.
High3D-01A failed 3D import could replace existing work

The current scene was cleared before saved texture images finished decoding.

Validate and decode the replacement first. A failed import preserves the scene and clears the file input for retry.

Reproduced on the baseline; malformed texture import preserves both existing meshes in the candidate.
HighSAVE-01The app could create files outside its own reopen limits

3D duplication bypassed the 200,000-triangle limit; scene saves lacked the 30 MB limit; brush totals could exceed the project validator’s 100-brush limit.

Enforce duplicate and scene-save limits, cap custom brushes across imports, and validate 2D frames before saving.

Baseline reached 234,496 triangles; candidate boundary browser checks and brush/save regressions pass.
Medium3D-02Duplicated texture paint lost editable layer state

Mesh duplication copied the material but did not clone its paint-layer canvases.

Clone the layer stack and canvases independently. Initialize the base-colour export canvas.

UV unwrap; save original and copy; compare layer data; repaint copy without changing original.
Medium3D-03GLB export could omit an existing rig animation

Animation export depended on the currently selected mesh being the rig.

Track the rig target separately and export its pose keys even when another mesh is selected.

Exported GLB contains skins and animation with an unrigged cube selected.
MediumVIDEO-01Very short speedpaints could export an empty video

The browser encoder could finish before producing a frame for a very short clip.

Hold the final frame until at least 500 ms for short exports.

Empty-video error reproduced; corrected one-stage WebM independently decoded with ffprobe.
MediumEXPORT-01Several export options were ignored or produced wrong backgrounds

Guides were missing at master size or misplaced in resized output; SVG ignored transparency; opaque formats did not consistently flatten empty pixels to white.

Draw guides before resizing, pass transparency through SVG, and composite white for JPG/TIFF/PSD/PDF.

Pixel regressions, SVG embedded-image check, and independently opened PNG/JPG/TIFF/PSD/PDF files.
MediumIMPORT-01Image and project imports had incomplete failure handling

A delayed image could land after a new document was created; invalid images lacked a useful error; later-frame failure could retain the rejected title/onion state.

Bind image decoding to its starting document, show decode errors, release temporary URLs, and restore project metadata on failure.

Real malformed PNG, delayed decode after New, artwork comparisons and rollback regression.
MediumPRIVACY-01Privacy information was hard to reach from the app

The local launcher did not serve privacy.html and the page was not part of the offline cache.

Add app, AI and Team privacy links; serve and precache the existing bilingual page; advance the cache to v12.

Local launcher response, new-tab privacy opening, RTL content and offline subfolder navigation.

Validation and its limits

Open acceptance blocker: export after path tracing.Viewport PNG export after path tracing timed out in both the long combined run and a separate fresh session using software graphics. Raster PNG export before tracing passed. The cause is not established: it may involve the app, the driver or software-renderer load. Do not treat the path-tracing export workflow as verified. Reproduce and resolve it on supported Windows hardware before release.

Verified

  • 67 automated tests pass, including seven new export, rollback and save-boundary regressions.
  • PDF files pass strict parsing and render independently. PNG, JPG, TIFF and PSD open with the expected pixel/background behaviour.
  • Animation and short speedpaint WebMs decode as real video. The ten-frame PNG ZIP passes CRC checks and includes timing metadata.
  • The GitHub-style /Rasmora-Studio/ subfolder supports online/offline 2D and 3D startup and the bilingual privacy page. The UV WASM asset is included in the offline cache.
  • Team checks use a real local server and two browser clients. The AI bridge’s missing-key path fails safely; no paid provider call was made.

  • Real Surface/Wacom devices: pressure, tilt, palm rejection, touch and shortcut remotes.
  • Supported Windows GPUs, display scaling, long sessions and realistic large projects.
  • Manual keyboard/screen-reader accessibility and Arabic/English font proofing on target devices.
  • Any production AI or hosted Team configuration, including access, HTTPS, persistence and backup operations.
  • Microsoft Store package certification. No signed MSIX/EXE was produced in this audit.

Keep the product claims accurate

The current master canvas is 1200 × 900. Larger export presets resample it. Projects are limited to 48 frames, 240 retained speedpaint stages and 100 MB; 3D scenes are limited to 200,000 triangles and 30 MB. Save projects regularly: crash-recovery autosave is not implemented.

PSD is a flattened RGB compatibility export. The PDF is a Device-CMYK raster proof, without an ICC-managed commercial print pipeline. Team shares whole project revisions and feedback; it does not merge simultaneous brush strokes. The 3D rig is basic, and paid AI requires a configured service. These limits should remain clear in the Store listing.

Apply the candidate, then test the installed app

  1. Save current artwork and back up the repository. Follow APPLY_FIX.txt in the ZIP to replace the app files while preserving folder paths.
  2. Wait for GitHub Pages deployment. Reopen online so service-worker cache rasmora-studio-v12 is installed, then close and reopen the app.
  3. On the deployed site, test New, drawing, undo/redo, save/reopen, PDF, short speedpaint, 3D and offline/privacy access.
  4. Investigate the repeatable post-tracing export timeout, then complete the Windows/device and package acceptance tests above before Store submission.
